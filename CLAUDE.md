# Working rules for this repository

This repository is a workshop exercise. **The application under test is at https://arrangility.github.io/shoptodo-workshop/ and is not part of this repository.**

## What matters here

1. **The specification is a document.** Read `spec/feature.md`. Do not ask the user to paste requirements into a prompt.
2. **Do one activity at a time.** Analysis, then design, then implementation, then execution, then completion. **Stop at the end of each and show your output before moving on.**
3. **Do not write test code during analysis or design.** Test conditions first. Cases second. Code third.

## When reviewing someone else's output

If you are asked to review test conditions or test cases that were produced elsewhere:

- **Work only from what you are given.** Do not look for other files, other tests, or anything outside this repository.
- **Look three ways.** Go deeper into one line of reasoning. Compare against how similar features are usually checked. Ask what would show that this set is not enough.
- **Name each gap, and quote the line of the specification that requires it.**

## Out of bounds

- **Do not fetch or read the source repository of the application under test.** Work from `spec/` and from the running application only.
